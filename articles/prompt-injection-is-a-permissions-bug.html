Prompt Injection Is a Permissions Bug

You can't sanitize natural language. You can remove a capability.

September 22, 2026 · 5 min read · research window 2025-06-01 to 2026-09-22

In June 2025, Microsoft patched a vulnerability in Microsoft 365 Copilot that researchers at Aim Security had named EchoLeak. Tracked as CVE-2025-32711 and rated 9.3 on the CVSS scale, it needed no click from the victim. An attacker sent a carefully written email to someone in the organization. When Copilot later pulled that email into its context while answering an ordinary question, the hidden instructions in it could get Copilot to leak data it had access to, from Outlook, OneDrive, SharePoint and Teams. Microsoft fixed it server-side and said there was no evidence of exploitation.

Nothing in EchoLeak was a bug in the usual sense. No buffer overflowed and no token leaked. The model did what language models do: it followed instructions it found in its context. The vulnerability was the combination of things the assistant was allowed to touch.

Prompt injection isn't a model-quality problem you wait out. It's a permissions problem you design out, at scoping time, one connector at a time.

Before

Prompt injection is a model weakness. Better models and input filters will fix it.

After

Assume the model will sometimes be fooled. Design so a fooled agent can't do much harm.

Turn

You can't sanitize natural language. You can remove a capability.

The same month, Simon Willison gave the pattern a name that has stuck: the lethal trifecta. An agent is exploitable when it has three things at once: access to private data, exposure to untrusted content, and some way to communicate externally. Any text an attacker can get in front of the model becomes a potential instruction, and if the agent can both read your secrets and send something out, those instructions can carry the secrets with them. Willison noted that researchers were reporting this exact exploit against production systems all the time, including Microsoft 365 Copilot, GitHub's official MCP server and GitLab's Duo chatbot.

His point about guardrail products was blunt. A filter that catches 95 percent of injection attempts sounds good, but in security it's a failing grade, because attackers don't stop at one try. Model providers won't solve this for you either. The defense that works is structural: make sure no single session has all three legs.

In October 2025, Meta published a practical version of the same rule, the Agents Rule of Two. Within a session, an agent should have no more than two of: processing untrustworthy inputs, access to sensitive systems or private data, and the ability to change state or communicate externally. If a workflow truly needs all three, it shouldn't run autonomously; it needs a human in the loop. The framing matters because it starts from the right assumption: injection will sometimes get through, so limit what a compromised session can do.

Before

Security reviews the agent once it's built.

After

The trifecta is decided in the integration list, which the FDE writes during scoping.

Turn

"Can you also connect it to the shared inbox?" is a security decision wearing a feature request's clothes.

This is why the problem lands on FDEs specifically. Nobody designs an exfiltration path on purpose. It gets assembled one reasonable request at a time. The pilot reads the CRM: private data. Week three, the customer asks for it to summarize inbound support email: untrusted content. Week five, someone wants it to post summaries to a webhook, or the chat UI starts rendering Markdown images, and the third leg arrives quietly, because fetching an image from an attacker-chosen URL is a way to communicate externally. Each step is a small change in a sprint review. Together they recreate EchoLeak.

The fix isn't to refuse the features. It's to split the sessions. The agent that reads untrusted email produces structured output and has no outbound tools. The agent that sends things never sees raw untrusted text. Outbound destinations are allowlisted. Where one flow really needs all three, a person approves the outbound step with the content in front of them.

Trifecta check for one agent session

Tick the capabilities this session has.

Every FDE has sat in the security review where someone asks, "Can it be tricked?" The wrong answer is a description of the system prompt and the filter vendor. The right answer is "Yes, assume it can. Here's everything a tricked session can reach, and here's why it can't reach all three." That answer wins the room because it's the same answer the security team would give about a human with the same access.

The case against

The objection is that removing a leg kills the use case. The whole point of an email assistant is to read your inbox and act on it. That's true for the product as a whole, but it doesn't have to be true for any single session. Splitting reader and actor sessions, allowlisting where data can go, and putting a person on the rare step that needs everything costs some latency and some engineering. Compare that to a 9.3 CVSS rating with your customer's name on it.

What this means for you

  • Draw the legs. For each agent session, list which tools or connectors provide private data, untrusted content and external communication.
  • Count quiet channels as outbound. Rendered Markdown images, link unfurls, webhooks and writes to shared documents all communicate externally.
  • Split sessions. Readers of untrusted content get no outbound tools; senders never see raw untrusted text.
  • Allowlist destinations for every outbound tool.
  • Put it in the SOW. "We assume prompt injection succeeds; this is the blast radius" is a sentence a CISO will sign.
24-hour action: Take your most-used agent and write down which tool gives it each leg of the trifecta. If all three show up in one session, raise it with the customer's security contact this week.

Quick facts

What was EchoLeak?

CVE-2025-32711, rated CVSS 9.3: a zero-click flaw in Microsoft 365 Copilot where a crafted email could get data pulled from the user's context. Microsoft fixed it server-side in June 2025 and reported no evidence of exploitation.

What is the lethal trifecta?

Simon Willison's name (June 2025) for an agent that combines access to private data, exposure to untrusted content, and the ability to communicate externally.

What is the Agents Rule of Two?

Meta's October 2025 guidance: within a session, an agent should have no more than two of untrustworthy inputs, access to sensitive systems or data, and the ability to change state or communicate externally.

Why not just add a filter?

In security, a filter that stops 95% of attacks is a failing grade: attackers keep trying until they find the rest.
